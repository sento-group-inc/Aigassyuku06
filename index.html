なぜ分身OSを作るのか

AIを「便利な質問箱」から「仕事を任せる相手」に変える。

予測利得AIが何を知っている状態で動くかが見える。
行為影響度毎回の説明をAGENTS.mdへ移し、次回から省略できる。
共有度10人全員が同じフォルダ構成で再現できる。

あのね、みなさんAIを使ってるじゃないですか。ChatGPTに聞く。Claudeに聞く。資料を作らせる。メール文を直させる。それ自体はもう珍しくないんですよ。

でも、たぶん同時にこういう感覚もあると思ってて。毎回、説明してませんか。「うちの会社はこうで」「このお客さんはこうで」「僕はこういう判断をしたくて」「この表現はうちっぽくないからやめて」。

社員を雇ったとして、毎朝その人に「うちの会社は何をしている会社です」から説明し直してたら、仕事にならない。でもAIにはそれをやっている。今日と明日でやるのは、ここを終わらせることです。

Before

AIに毎回背景を説明し、出てきたものを場当たり的に直す。

After

Codexが会社・判断軸・失敗パターンを読み、作業単位で任せられる。

今日作るのは「全自動で放置する仕組み」ではなく、引き継ぎ書を渡し、仕事を任せ、レビューして育てる環境です。

grill-me型プロンプトを単語登録する

「AIに任せたい作業は？」では浅い。先に業務の因果と依存関係を掘る。

予測利得自分が何を任せたいのかではなく、何が詰まりかが見える。
行為影響度深掘り結果をAGENTS / state / memoryに入れる。
共有度単語登録で誰でも同じ入口から始められる。

オープンクエスチョンで「自分の業務でAIに任せたい作業を書いてください」と言っても、たいてい浅くなります。本人もまだ因果を掘れていないからです。

そこで先に、AIに執拗にインタビューさせる。AI Heroで紹介されているgrill-me系の発想を、合宿の最初の道具にします。前に身につけたスキルを、次の学習の入口に使う。これが因果連鎖です。

参考: AI Hero: My Grill Me Skill Has Gone Viral
単語登録するプロンプト
この件のあらゆる側面について執拗にインタビューして。共通理解に達するまで、デザインの因果関係と決定事項間の依存関係を1つずつ解決し、各質問に推奨回答も提示して。

Macユーザ辞書に登録

  1. システム設定を開く。
  2. キーボード → テキスト入力 → ユーザ辞書を開く。
  3. 入力に ぐりる、変換に上のプロンプトを登録する。

Google日本語入力に登録

  1. メニューバーのGoogle日本語入力アイコンから「辞書ツール」を開く。
  2. 新規エントリーで、よみに ぐりる、単語にプロンプトを入れる。
  3. 品詞は短縮よみ、または名詞でよい。
深掘り結果をCodex環境へ反映
今のインタビュー結果を、次の3つに分けて整理してください。
1. AGENTS.mdに入れるべき恒久ルール
2. state.mdに入れるべき現在の重点テーマ
3. memory.mdに入れるべき長期的な会社情報・判断軸

そのうえで、初回の実務タスクとして一番筋が良いものを1つ選んでください。

Context7 / GitHub / Exa をMCPで取り込む

Codexのチャットから、外部の手と目を増やす。

予測利得最新ドキュメント、GitHub、Web検索を参照できる。
行為影響度config.tomlをCodexに作成・更新させる。
共有度プレースホルダ方式なのでAPIキーを公開せず説明できる。
公開サイトに本物のAPIキーを載せない。参加者は自分の画面で発行し、Codexに置換を依頼します。
MCP一括設定プロンプト
あなたはセットアップ担当です。以下を順に実行してください。

1. node / npx / uv / mcp-proxy が使えるか確認。不足があれば Homebrew 等で導入方法を提案し、実行前に私に確認してください。
2. ~/.codex/config.toml を次の内容で作成または更新してください。既存設定があれば破壊せずマージしてください。
3. YOUR_CONTEXT7_API_KEY / YOUR_EXA_API_KEY / YOUR_GITHUB_TOKEN はプレースホルダのまま書いてください。
4. 完了したら /mcp で確認する手順を教えてください。

--- config.toml 本文 ---

model = "gpt-5-codex"
model_reasoning_effort = "medium"

[features]
web_search_request = true

[mcp_servers.context7]
command = "npx"
args = ["-y", "@upstash/context7-mcp", "--api-key", "YOUR_CONTEXT7_API_KEY"]

[mcp_servers.github]
command = "mcp-proxy"
args = ["--transport", "streamablehttp", "-H", "Authorization", "Bearer YOUR_GITHUB_TOKEN", "https://api.githubcopilot.com/mcp/"]

[mcp_servers.exa]
command = "npx"
args = ["-y", "mcp-remote", "https://mcp.exa.ai/mcp?exaApiKey=YOUR_EXA_API_KEY"]

[mcp_servers.chrome-devtools]
command = "npx"
args = ["chrome-devtools-mcp@latest"]
キー取得後の置換
YOUR_CONTEXT7_API_KEY を ctx7sk-... に
YOUR_EXA_API_KEY を Exaのキーに
YOUR_GITHUB_TOKEN を GitHubのトークンに
置き換えて config.toml を更新してください。
更新後、/mcp で確認する手順も出してください。
MCP役割使いどころ
Context7ライブラリ最新ドキュメント参照GAS / Vercel / フレームワーク調査
GitHubIssue / PR / repo情報便利リポジトリ取り込み
ExaWeb・コード検索X投稿や記事の裏取り

Code.gs
function doGet() {
  return HtmlService.createHtmlOutputFromFile('index')
    .setTitle('社内アプリ')
    .setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL);
}

function getItems() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
  const values = sheet.getDataRange().getValues();
  const headers = values.shift();
  return values.map(row => {
    const item = {};
    headers.forEach((header, index) => item[header] = row[index]);
    return item;
  });
}

Macを起動維持してCodexを走らせる

長い作業を任せるときは、Macが寝ない状態を作る。

予測利得途中停止の原因がMacのスリープか切り分けられる。
行為影響度6時間だけ起動維持して作業させる。
共有度標準コマンドとGUIアプリの2択を用意。
6時間スリープさせない
caffeinate -dimsu -t 21600
  • -d: ディスプレイをスリープさせにくくする。
  • -i: システムスリープを防ぐ。
  • -m: ディスクスリープを防ぐ。
  • -s: AC電源接続時のスリープを防ぐ。
  • -u: ユーザー操作があった扱いにする。
  • -t 21600: 21600秒、つまり6時間。
GUIがよければ Amphetamine を使う。メニューバーから「指定時間だけ起動維持」を選べるので、講義中や長いCodex作業に向いています。
