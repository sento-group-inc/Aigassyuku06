1Homebrew のインストール

Homebrewは「Macのアプリストア」のようなもの。これを入れると、ほぼすべての開発ツールを1行のコマンドでインストールできるようになります。

Homebrew は macOS 専用です。インストールには 管理者パスワード が必要です。

ターミナルの開き方（初めての人向け）

1
Finder を開く
Dockの一番左にある笑顔のアイコン、または画面左上の 🔍 で「Finder」と検索。
2
「アプリケーション」→「ユーティリティ」→「ターミナル.app」
または Spotlight（⌘ + Space）で「terminal」と入力して起動。黒い画面が出ればOK。
3
コマンドを貼り付けて Enter
⌘ + V で貼り付けられます。右クリック → 「ペースト」でもOK。

インストールコマンド

① Homebrew をインストール
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
パスワードを入力するときの注意
Macのパスワードを求められます。入力しても画面には文字が表示されません（セキュリティのため）。でも入力はされています。そのまま Enter を押してください。

PATH を通す（Apple Silicon Macの場合）

M1/M2/M3/M4 Mac を使っている場合、インストール後にターミナルの指示に従って PATH を通します。インストール完了時に 「Run these two commands...」 と表示されるので、その2行をコピーして実行してください。

② PATH の設定（表示された内容をそのまま実行。以下は例）
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
③ 設定を反映
eval "$(/opt/homebrew/bin/brew shellenv)"

インストール確認

④ バージョン確認
brew --version
「Homebrew 4.x.x」のような表示が出ればインストール成功です。
わからなければAIに聞こう！
エラーが出たら、赤いメッセージをそのままコピーして ChatGPT か Claude に「このエラーの直し方を教えて」と貼り付けてください。ほとんどのエラーは解決できます。

よく使う brew コマンド

コマンド意味使う場面
brew search 名前インストールできるものを探すZoomやChromeなど、名前が合っているか確認したい時
brew install 名前CLIや開発ツールを入れるNode.js、Git、gogcliなど
brew install --cask 名前Macアプリを入れるChrome、VS Code、ngrokなど
brew list入っているものを見る「もう入ってる？」を確認したい時
brew updateHomebrewの情報を更新するインストール前に情報を最新にする
brew upgrade入っているものを更新する古いツールをまとめて更新する
参考（常設）: Homebrew インストール方法 — 株式会社キカガク / Homebrew 公式

4スマホからリモートで指示を出す

AI組織のCEOは、Macの前にいる必要はありません。Codex も Claude Code も、スマホから指示・確認・承認できます。長い作業を任せながら移動する、会議中に方向修正する — リモコン操作が当日の基本動作になります。

Codex Mobile（ChatGPTアプリ）Mac側のCodex Appが動いていれば、スマホのChatGPTアプリから進捗確認・承認・指示ができる

A. Codex Mobile（ChatGPTアプリ）

前提
Codex Mobileはスマホ単体でMac内のファイルを編集するものではありません。Mac側のCodex Appが動いていて、その作業状態をスマホのChatGPTアプリから見る・動かす、という理解です。

事前にやること

1
Mac側のCodex Appを最新版にする
Codex Appを開き、右上などに更新表示が出ていたら更新する。古いままだとスマホ側が「デスクトップアプリを待っています」から進まないことがあります。
2
スマホにChatGPTアプリを入れる
App Store / Google Play から公式ChatGPTアプリを入れ、Mac側と同じChatGPTアカウントでログインする。
3
スマホ側でCodexを開く
ChatGPTアプリ内のCodexを開く。表示されない場合は、アプリ更新、同じアカウントか、ロールアウト状況を確認する。
4
Mac側の「Codex mobileを設定」を押す
スマホが待機画面になったら、Mac側のCodex Appに戻り、左メニューや案内に出る「Codex mobileを設定」を押して接続する。

合宿での使いどころ

長い作業を見守る調査、画像整理、HTML生成、テスト実行など、Mac側で進む作業をスマホから確認できる。
承認待ちを止めないCodexが「このコマンドを実行していい？」と聞いたとき、席を外していても気づける。
移動中に方向修正出力を見て「この方針で」「そこは違う」と短く返せる。
ただしMacは必要Mac側のCodex App、作業フォルダ、認証、起動状態が土台。スマホはリモコン。
参考（常設）: Codex for mobile（OpenAI） / Work with Codex from anywhere（OpenAI） / Codex Studioさんの解説ポスト

B. Claude Code Remote Control

Claude Code には組み込みのリモートコントロール機能があります。ターミナルで1コマンド実行するだけで、スマホブラウザ（claude.ai/code）から同じセッションを操作できます。Codex Mobileと同じ「リモコン」用途を、Claudeで実現する方法です。

仕組み Mac側で claude rc を実行 → ターミナルにセッションURLとQRコードが表示 → スマホで読み取るだけで接続
常時有効にする Claude Code内で /config → 「Enable Remote Control for all sessions」を true にセットすれば、毎回コマンドを打たなくて済む

セットアップ手順

1
Claude Code をインストール（まだの場合）
詳細は Section 6。npm install -g @anthropic-ai/claude-code で入ります。
2
常時有効化（推奨）
Claude Code を起動し、/config を入力 → 「Enable Remote Control for all sessions」を true に設定する。以降は毎回自動でリモコン待機状態になる。
3
リモートセッションを開始
プロジェクトフォルダで claude rc を実行するか、既存セッション内で /rc と打つ。ターミナルにURLとQRコードが表示される。
4
スマホで接続
スマホのカメラでQRコードを読み取るか、表示されたURLを claude.ai/code で開く。接続すればスマホから指示できる。
リモートコントロールを起動（プロジェクトフォルダで実行）
claude rc
既存セッション内で起動する場合（チャット欄に入力）
/rc
スマホ側は専用アプリ不要。ブラウザ（Safari / Chrome）で claude.ai/code を開くだけで接続できます。
参考（常設）: Claude Code リモートコントロール解説（DevelopersIO）

7ngrok のインストール

ngrok はローカルで動かしているサーバーを、インターネット経由で一時的に公開するツール。「自社の方針HTMLを作って今すぐURLで共有したい」ときに便利。

Vercel との違いVercel = GitHubに push するたびに自動デプロイ。恒久公開。
ngrok = コマンド1行で今すぐ外部公開。一時的な共有向け。
使いどころ会議中に「今作ったHTMLを見せたい」「スマホで確認したい」「チームに即共有したい」
① ngrok をインストール
brew install --cask ngrok

インストール後は ngrokダッシュボード でアカウント作成してトークンを取得してください（無料）。

② 認証（YOUR_NGROK_TOKEN を自分のトークンに置き換え）
ngrok config add-authtoken YOUR_NGROK_TOKEN

10Composio — MCP をまとめて管理する

MCP を1つずつ手で設定するのが面倒な人向け。Composio Connect を使うと GitHub / Asana / Slack / Notion など 1000以上のツール を、1つのMCP接続から扱えるようになります。

Composio とは

MCPのハブ https://connect.composio.dev/mcp を1本つなぐと、Composio側でGitHub、Asana、Slackなどの接続を管理できます。
なにが便利か 通常はツールごとにAPIキーやOAuthを管理します。Composioを使うと、AIが必要なアプリを探し、ブラウザで認証し、接続状態をダッシュボードで見られます。

仕組みのイメージ（Composio なし vs あり）

Composio なし

flowchart TB Codex["Codex / Claude"] --> C7["Context7\nAPIキー個別設定"] Codex --> GH["GitHub Token\n個別設定"] Codex --> EX["Exa APIキー\n個別設定"] Codex --> AS["Asana PAT\n個別設定"]

Composio あり

flowchart TB Codex["Codex / Claude"] --> CP["Composio Connect\nMCP URL 1本で管理"] CP --> C7["Context7"] CP --> GH["GitHub"] CP --> AS["Asana"] CP --> SL["Slack / Notion\nほか1000+ツール"]

セットアップ手順

1
アカウント作成
dashboard.composio.dev でアカウントを作成し、ダッシュボードを開く。
2
Connect Apps を開く
GitHub、Asana、Slackなど、使いたいアプリを選んでブラウザでOAuth認証する。
3
Composio MCP をCodexに追加
Codexのチャットに下の依頼を貼る。手でconfigを書くより、Codexに設定してもらう方が当日再現しやすい。
4
動作確認
Codexに「Composioで使えるツールを探して」と聞く。接続済みアプリが出ればOK。
Codexに貼る設定依頼
ComposioをCodexで使えるように設定してください。

+Obsidian（任意） — Markdownファイルをビジュアルで管理する

AGENTS.md / memory.md / brand-voice.md などのファイルを、GUIで管理・検索したい人向けのオプションツールです。必須ではありません。Finderやエディタで管理しても同じ効果があります。

Obsidian が便利な場面ファイルが増えてきて「あの情報どのファイルだっけ」と探す時間が増えてきたとき。全文検索・タグ・リンクでファイル間を行き来できる。
Obsidian なしでOKな場面まだファイルが5〜10個程度の初期段階。Codexがファイルを直接読み書きするので、GUI管理はあくまで人間側の便宜。
インストール（任意）
brew install --cask obsidian

インストール後は 作業フォルダ（codex-bunshin-os/）をVaultとして開くだけでOKです。Codexが作ったmarkdownファイルをそのまま表示・編集できます。

Obsidian の「Sync」機能（有料）は使わなくてOK。ファイルはローカルに置いてGitで管理します。
