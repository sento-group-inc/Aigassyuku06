用語プライマー — AGENTS.md / CLAUDE.md とは

この合宿で何度も出てくる用語を先に整理します。

AGENTS.mdAIエージェント向けのREADME。Cursor、Copilot、Codex CLIなど複数ツールで共通利用できる指示置き場。Linux Foundation AAIF で標準化が進む。
CLAUDE.mdClaude Code専用の指示ファイル。@import、Planモードなど、Claude Code固有の機能を書く場所。
共通 vs 専用会社情報・判断軸・安全ルール → AGENTS.md。Claude固有の設定 → CLAUDE.md。重複を避けてシンボリックリンクで互換もできる。
memory.md / state.mdmemory = AIが長期で覚えてほしい会社・業務情報。state = 今この瞬間の重点テーマ・ブロッカー。セッションをまたいでコンテキストを保持する。
用語意味合宿での使い方
インストラクション・バジェットAIが安定して守れる指示量の限界。150〜200指示を超えると崩れやすい。AGENTS.mdを肥大化させず、SkillやDocsに分ける。
Context Rot会話が長くなるほど、AIの参照・判断精度が落ちる現象。必要な資料だけを読ませる。全部貼らない。
Progressive Disclosure必要な時に必要な情報だけ開く設計。AGENTS.mdを目次にし、詳細はskillsやdocsに分ける。

1Homebrew のインストール

Homebrewは「Macのアプリストア」のようなもの。これを入れると、ほぼすべての開発ツールを1行のコマンドでインストールできるようになります。

Homebrew は macOS 専用です。インストールには 管理者パスワード が必要です。

ターミナルの開き方（初めての人向け）

1
Finder を開く
Dockの一番左にある笑顔のアイコン、または画面左上の 🔍 で「Finder」と検索。
2
「アプリケーション」→「ユーティリティ」→「ターミナル.app」
または Spotlight（⌘ + Space）で「terminal」と入力して起動。黒い画面が出ればOK。
3
コマンドを貼り付けて Enter
⌘ + V で貼り付けられます。右クリック → 「ペースト」でもOK。

インストールコマンド

① Homebrew をインストール
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
パスワードを入力するときの注意
Macのパスワードを求められます。入力しても画面には文字が表示されません（セキュリティのため）。でも入力はされています。そのまま Enter を押してください。

PATH を通す（Apple Silicon Macの場合）

M1/M2/M3/M4 Mac を使っている場合、インストール後にターミナルの指示に従って PATH を通します。インストール完了時に 「Run these two commands...」 と表示されるので、その2行をコピーして実行してください。

② PATH の設定（表示された内容をそのまま実行。以下は例）
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
③ 設定を反映
eval "$(/opt/homebrew/bin/brew shellenv)"

インストール確認

④ バージョン確認
brew --version
「Homebrew 4.x.x」のような表示が出ればインストール成功です。
わからなければAIに聞こう！
エラーが出たら、赤いメッセージをそのままコピーして ChatGPT か Claude に「このエラーの直し方を教えて」と貼り付けてください。ほとんどのエラーは解決できます。
参考（常設）: Homebrew インストール方法 — 株式会社キカガク / Homebrew 公式

2Node.js と Git のインストール

Homebrew が入れば、残りは1コマンドずつ。エラーが出たら AIに聞きながら進めてOKです。

Node.js

JavaScript の実行環境。多くのCLIツールが Node.js ベースなので必須。

① Node.js をインストール
brew install node
② バージョン確認
node --version
③ npm も確認
npm --version

Git

コードのバージョン管理。Vercel公開でも使う。

④ Git をインストール
brew install git
⑤ バージョン確認
git --version
わからなければAIに聞こう！
「node --version が通りません」のように状況をそのまま伝えればOK。「私は Mac の M3 チップを使っています」のように環境を添えるとより正確に答えてくれます。

5ngrok のインストール

ngrok はローカルで動かしているサーバーを、インターネット経由で一時的に公開するツール。「自社の方針HTMLを作って今すぐURLで共有したい」ときに便利。

Vercel との違いVercel = GitHubに push するたびに自動デプロイ。恒久公開。
ngrok = コマンド1行で今すぐ外部公開。一時的な共有向け。
使いどころ会議中に「今作ったHTMLを見せたい」「スマホで確認したい」「チームに即共有したい」
① ngrok をインストール
brew install --cask ngrok

インストール後は ngrokダッシュボード でアカウント作成してトークンを取得してください（無料）。

② 認証（YOUR_NGROK_TOKEN を自分のトークンに置き換え）
ngrok config add-authtoken YOUR_NGROK_TOKEN
ここまでやれば当日すぐ使えます。詳細な使い方は本編 Section 16 で。

7Composio — MCP をまとめて管理する

MCP を1つずつ手で設定するのが面倒な人向け。Composio を使うと GitHub / Asana / Slack / Notion など 1000以上のツール を、ダッシュボードから一元管理できます。

Composio とは

MCPのハブ Composio の API キー1つで、1000以上の外部ツールに Codex / Claude から接続できます。ツールごとのAPIキーやOAuth設定を Composio が代わりに管理してくれます。
なにが便利か 通常は Context7・GitHub・Exa それぞれのAPIキーを config.toml に書く必要があります。Composio を使うと Composio の API キー1つで複数ツールに繋がります。

仕組みのイメージ（Composio なし vs あり）

Composio なし

flowchart TB Codex["Codex / Claude"] --> C7["Context7\nAPIキー個別設定"] Codex --> GH["GitHub Token\n個別設定"] Codex --> EX["Exa APIキー\n個別設定"] Codex --> AS["Asana PAT\n個別設定"]

Composio あり

flowchart TB Codex["Codex / Claude"] --> CP["Composio Hub\n1つのAPIキーで管理"] CP --> C7["Context7"] CP --> GH["GitHub"] CP --> AS["Asana"] CP --> SL["Slack / Notion\nほか1000+ツール"]

セットアップ手順

1
アカウント作成（無料）
dashboard.composio.dev でアカウントを作成。
2
APIキーを取得
ダッシュボード右上の API Keys セクションから YOUR_COMPOSIO_API_KEY をコピー。
3
Composio MCP を config.toml に追加
Codex の設定ファイル（~/.codex/config.toml）に追記する。
4
ブラウザで認証
Codex から Composio にアクセスすると認証ウィンドウが開く。ダッシュボードで各ツールを接続すれば完了。
config.toml に追加（YOUR_COMPOSIO_API_KEY は自分のキーに置き換え）
[mcp_servers.composio]
command = "npx"
args = ["-y", "@composio/mcp@latest", "--api-key", "YOUR_COMPOSIO_API_KEY"]
Composio は任意です
合宿では各MCPを個別設定する方法（Section 06）をメインで説明します。Composio は「もっと楽にまとめて管理したい人向け」の選択肢として紹介します。
わからなければAIに聞こう！
「Composio のセットアップ方法を教えて」と Claude か Codex に聞くと、ダッシュボードの操作手順も含めて答えてくれます。
参考（常設）: Composio × Codex セットアップ（公式） / Composio ダッシュボード
