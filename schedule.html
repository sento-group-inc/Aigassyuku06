合宿スケジュール

2026年6月9日(火)〜10日(水) — 千葉・古民家

まずオリエンテーション — このMacをコックピットにする

今日のゴールは、みんなのMacを仕事のコックピットにすることです。NotebookLM、Google Sheets、GitHubリポジトリ、指示書HTML、Vercel公開URLまで、この1台から扱える状態を作ります。

午前は全員で足並みを揃えられるセットアップを先に通します。午後は各自の制作時間です。grill-meで深掘りしながら、公開済みの仮HTMLを自分の業務改善HTMLへ育てていきます。

背景：なぜこの2日があるのか

みんなAIは使っている。でも毎回「うちの会社はこうで」「この判断軸で」「この表現はうちっぽくない」と説明し直して、本題の前に疲れている。さらに、一人のAIに全部やらせて品質が安定しない。この「再説明コスト」をゼロにし、自分専用に育てたAIに業務を任せられる状態を作る——それがこの2日の狙いです。

ゴール：何を持ち帰るか

公開導線GitHub / Vercel / ngrokで、仮HTMLをURL共有できる。
AIの手足agent-browser、gbrain、repo-intakeで調査・確認・記憶の入口を持つ。
業務改善HTMLの種午後に深掘りして育てる、空欄付きの制作物。
分身OS（AGENTS.md群）gbrain導入後に、会社・判断軸・現在地を記憶として整える。

進め方：午前は共通セットアップ、午後は各自制作

まずは全員で、OutputをURLで出せるところまで揃えます。

同期したリポジトリをCodex / Claudeで開いて、下の合言葉を貼ります。午前はセットアップと仮HTML公開を優先し、AGENTS.md / memory / state は gbrain を入れた後に作ります。

▶ 開始の合言葉（Codex / Claude にそのまま貼る）
このリポジトリの journey/README.md を開いて読んで、その手順で私を導いてください。

※ 下のタイムラインが正本です。本編の各Sectionは、必要になった時に引く辞書として使います。

では、準備ができた人から Step 0 事前準備 と Step 1 スケジュール確認 を済ませ、午前セットアップへ進みましょう。

Day 1

6月9日(火) — セットアップと作業

09:00 受付・開会 自己紹介。今日の目的は「このMacをAIコックピットにする」こと。まず TOP から Step 0 / Step 1 を確認する。
09:30 共通セットアップ — まず公開導線まで通す Codex起動、GitHubログイン、合宿リポジトリ同期、Vercelログイン、仮の業務改善HTML公開まで進める。
→ 事前準備 / Vercel公開 / ngrok一時公開
11:00 ごろ AIの手足を増やす — agent-browser / gbrain / repo-intake 公開URLをAIに読ませる agent-browser、記憶の器になる gbrain、便利リポジトリを導入判断する repo-intake を揃える。AGENTS.md / memory / state は gbrain 後に作る。
agent-browser / gbrain / repo-intake演習 / 事前準備
13:00 昼食・休憩 仮HTMLのURL、Vercel/ngrok、agent-browser、gbrain、repo-intake のどこで詰まっているか確認する。
13:30〜18:00 それでは深掘りをやっていきましょう！ — grill-meから各自制作へ ここからは各自制作。grill-meで業務を深掘りし、仮の業務改善HTMLへ反映する。必要に応じて Sheets、NotebookLM、Asana、MCP を足す。
各セクションへ飛ぶ：grill-me / AGENTS / gogcli / NotebookLM / Asana / repo-intake
18:00 URL付きの業務改善HTMLの種を共有 完成度は問わない。公開URLがあり、午後の深掘り結果が反映され始めている状態ならOK。明日10時に何を見せるかを声に出す。
18:30〜 夕食・夜の自由作業 成果発表に向けて作業継続。詰まったら相互サポート。

午前セットアップのマイルストーン

Codex起動確認 作業フォルダをCodexで開き、チャットが動く状態
grill-me単語登録 「ぐりる」と打つとプロンプトが出る状態
Vercel / ngrok公開 仮の業務改善HTMLがURLで見える状態
agent-browser / gbrain / repo-intake 公開確認、記憶化、導入判断の入口がある状態
Day 2

6月10日(水) — 成果発表と振り返り

09:00 朝作業・発表の最終準備 業務改善HTMLの「種」に、現状の詰まり・判断材料・次の2週間の方針を足す。完成させる必要はない。仕上げ・磨き込みは帰ってからでOK。
10:00 業務改善HTMLの種を発表（各自10分） 自分の業務改善HTMLの種をURLまたはローカル画面で見せる。完成度ではなく、Action・Output・次の2週間の方針を話す。
11:00 振り返り・全体ディスカッション 詰まりのパターン共有、個人OSからチーム標準へ進める時の論点、今後の運用について。
12:00 閉会・撤収

成果発表のフォーマット（各自10分）

① 起こしたいAction 誰が何を判断・実行できるようにするためのHTMLかを最初に話す。
② 現状の詰まり 何が止まっているのか。判断、情報、作業、共有のどこが詰まりか。
③ 作ったOutputの種 業務改善HTMLの種、シート、Vercel公開URLなど。完成していなくてよい。
④ 次の2週間の方針 誰が何をするか。AIに任せる作業、人間が決める作業を分ける。
発表はAGENTS.mdの読み上げではありません。自分の業務改善HTMLの種を見せて、どのActionが起きるのかを話す場です。
HTMLは「種」でOK。磨きは持ち帰り。
合宿で完成させる必要はありません。種ができたら、あとは帰ってから磨く。これが合宿の翌日からの「最初のやること」になります。
