合宿スケジュール

2026年6月9日(火)〜10日(水) — 千葉・古民家

まずオリエンテーション — この2日で何をするか

最初に全体像だけ掴んでください。「何のために・何を・どう進めるか」がここで分かります。あとは各自のペースで始めてOKです。

背景：なぜこの2日があるのか

みんなAIは使っている。でも毎回「うちの会社はこうで」「この判断軸で」「この表現はうちっぽくない」と説明し直して、本題の前に疲れている。さらに、一人のAIに全部やらせて品質が安定しない。この「再説明コスト」をゼロにし、自分専用に育てたAIに業務を任せられる状態を作る——それがこの2日の狙いです。

ゴール：何を持ち帰るか

分身OS（AGENTS.md群）会社・判断軸・口調を読んだAI環境。毎回の説明が要らなくなる。
AIのコックピット役割分担したAIに、操縦席から業務を振れる。あなたがCEO。
業務改善HTMLの種自分の業務が前に進む成果物の種。磨きは持ち帰り。
続けられる型失敗をAGENTS.mdに追記し、週次で手入れする習慣。

進め方：journeyガイドに沿って対話で進める（ここが本体）

基本は journey ガイドに沿って、AIとの対話で進めます。

同期したリポジトリをCodex / Claudeで開いて、下の合言葉を貼るだけ。あとはAIがあなたのペースに合わせて質問しながら導いてくれます。対話をじっくりやりたい人は深く、設定を先に進めたい人はサクサク。隣と進み方が違ってOKです。

▶ 開始の合言葉（Codex / Claude にそのまま貼る）
このリポジトリの journey/README.md を開いて読んで、その手順で私を導いてください。

※ 下のタイムラインや本編の各Sectionは「辞書」です。journeyを進める中で、必要なツールの手順だけ本編から引いて使います。各時間のリンクから該当セクションに飛べます。

では、準備ができた人から Session 01（文脈エンジンを作る） を始めましょう。

Day 1

6月9日(火) — セットアップと作業

09:00 受付・開会 自己紹介。合宿の目的と全体像を確認。 → Section00 全体像
09:30 深掘り・IPOA・環境作り（Section 01-06） grill-me登録 → IPOA → AGENTS.md作成 → MCP設定まで。Codexインストールは事前準備ページに寄せる。
→ 本編 Section01〜06 / IPOA / 事前準備
11:00 ごろ grill-me実行タイム 全員が自分の業務をgrill-meで深掘り。概要.mdを生成する。これが午後の各自作業の土台になる。 → Section02 grill-me
13:00 昼食・休憩 セットアップの完了状態を各自確認。詰まっていたら午後前半に解消する。
14:00〜18:00 各自作業 — まず「当日コア」を1本通す 当日コア（全員）：Skill化 → gogcli（Sheets）→ NotebookLM（資料）→ Asana（タスクのコックピット）→ 業務改善HTMLの種 → Vercel/ngrokで公開。
後日でOK（興味があれば）：agmsg、agent-browser、エージェント作成、GASの作り込み。全部を当日やろうとせず、自分の業務が1つ前に進む状態を優先。
各セクションへ飛ぶ：Skill化 / gogcli / NotebookLM / Asana / Vercel / ngrok / リポジトリ一覧
18:00 翌朝の発表HTMLを全体に共有 「明日10時にどの業務改善HTMLを見せるか」を声に出す。完成度より、Actionが定義されていることを優先。 → IPOAで整理
18:30〜 夕食・夜の自由作業 成果発表に向けて作業継続。詰まったら相互サポート。

Codex起動確認 作業フォルダをCodexで開き、チャットが動く状態
grill-me単語登録 「ぐりる」と打つとプロンプトが出る状態

Day 2

6月10日(水) — 成果発表と振り返り

09:00 朝作業・発表の最終準備 業務改善HTMLの「種」にIPOA・現状の詰まり・次の2週間の方針を足す。完成させる必要はない。仕上げ・磨き込みは帰ってからでOK。 → IPOA
10:00 業務改善HTMLの種を発表（各自10分） 自分の業務改善HTMLの種をURLまたはローカル画面で見せる。完成度ではなく、Action・Output・次の2週間の方針を話す。
11:00 振り返り・全体ディスカッション 詰まりのパターン共有、個人OSからチーム標準へ進める時の論点、今後の運用について。
12:00 閉会・撤収

成果発表のフォーマット（各自10分）

① IPOA Input / Process / Output / Action。特にActionを最初に話す。
② 現状の詰まり 何が止まっているのか。判断、情報、作業、共有のどこが詰まりか。
③ 作ったOutputの種 業務改善HTMLの種、シート、Vercel公開URLなど。完成していなくてよい。
④ 次の2週間の方針 誰が何をするか。AIに任せる作業、人間が決める作業を分ける。
発表はAGENTS.mdの読み上げではありません。自分の業務改善HTMLの種を見せて、どのActionが起きるのかを話す場です。
HTMLは「種」でOK。磨きは持ち帰り。
合宿で完成させる必要はありません。種ができたら、あとは帰ってから磨く。これが合宿の翌日からの「最初のやること」になります。
